## 60秒开始
1. 从仓库根目录阅读，不要再套一层 `seo-ai-project/`。人先看 [PROJECT_BRIEF.md](PROJECT_BRIEF.md)。
2. 将 [START_HERE_PROMPT.md](START_HERE_PROMPT.md) 的内容贴给AI，并让它读取本仓库里的文件。不要只发一个它打不开的压缩包路径。
3. AI先读下列核心文件，返回“事实/证据缺口/3项改进/一个60分钟下一步”；当前只评审，不自动写代码、买域名、部署产品、发消息或改飞书。

## 推荐阅读顺序与上下文预算
- 核心启动：本文件 → PROJECT_BRIEF → AI_WORKING_AGREEMENT → 00_CONTEXT/STATE → 02_PRACTICE/CANDIDATES → 02_PRACTICE/DAY_01 → CONFLICTS_AND_EVIDENCE。约1–2万中文字符量级，以 `04_GAPS_AND_AUDIT/reading_budget.json` 实测为准；先留足对话空间。
- 设计路径：knowledge_map.json → 10篇 topics → STAGE_GATES → DAILY_14_DAYS → 相应模板。不要先塞所有案例。
- 检索证据：SOURCES.jsonl/CSV用标题、分类或ID找到相关摘要，按需读取；精确ID是文档标识，不是授权凭据。
- 历史深读：legacy里含完整自写主题对照（第8节含后续增量）及骨干笔记，不能把早期进度当最终进度。
- 不支持文件夹的AI：`ALL_KNOWLEDGE.md` 合并了全部去敏单篇摘要、主题综合及历史笔记，另有 `01_KNOWLEDGE/merged_parts/` 分块。**不要一次塞全量**。分块只是传输单位，非独立证据层级；先核心启动，按查询挑相关篇章。token预算按字符粗估范围，不是模型精确计数。
