## 要点
2026-09-07，王焱反思自己曾在配置建议里写「静态站开 OWASP Core Ruleset 几乎零误伤」。后来在 Security Events 里看到首页一次普通访问（切中文、走相机入口的两个自有参数）被拦：规则是入站异常分超过阈值，41 分对 40 分，同时 js_detection 显示已通过浏览器检测。他纠正一个判断：这套规则不是和 Cloudflare Managed Ruleset 一样的签名黑名单，而是打分器，多条启发式规则累加超过阈值就动作；松紧由 Paranoia Level（PL1–PL4）和分数阈值（文中写可选 60、40、25）共同决定，单看一个旋钮没有意义。官方默认是 PL1+阈值40；官方建议的从严起步是 PL4+60。他实际用了 PL4+40，比官方从严档还紧，才会拦下这次请求。他还指出官方文档顶部就警告该规则集容易误报，在已开 Managed Ruleset 和 attack score 时只有边际收益，必须持续盯自己的流量来调。他认为静态页面请求几乎没有「输入里藏载荷」可检测，真正需要防护的是接受用户输入的端点；于是把 PL 降回 1、阈值提到 60，并把规则作用域收敛到 /api/ 路径。他还建议不确定时先把动作改成 Log 跑一段时间再看「本来会拦谁」。复核时他导出约 14.5 小时 171 条全部为 block 的事件：异常分类拦截变为零，剩下是具体签名和浏览器完整性检查；再用站上真实路由表比对被拦路径，命中真实页面的为零，被拦的都是不存在的敏感路径探测。搜索引擎爬虫为零；有来自 Google ASN 的扫描，但作者强调 ASN 属于 Google 不等于是 Googlebot。还发现两组套用正规 UA 的探测（自称官方抓取器或学术机构，实际在翻密钥类路径），用来说明判断请求要看它要什么，不要只看自称是谁。他坦承改配置前没有先导出旧窗口，因此无法量化误杀了多少真实访客、持续几天，只剩间接推断；规矩应是先导出证据再改配置。最后提醒：纯静态或 SSG 站他现在倾向这套规则干脆不要开；有 API 再开也要加路径作用域。不要只看 block，托管质询更容易卡住走代理、老浏览器或辅助工具的用户，且不会出现在只筛 block 的列表里。被拦的人通常不会投诉，GA 也看不到，因为页面没加载。

2026-10-11，作者禾急把国庆前后多篇群友复盘合并成一份对照，并开篇声明：数据都是自报，时间主要在2026年9月底至10月上旬，金额有美元、澳元、港币，不同网站可能重复统计，不能直接相加，大部分是扣除支付手续费和模型成本前的流水。他归纳的闭环是：发现新需求 → 做出最小产品 → 接入支付 → 从 ChatGPT、Google 或社媒获得访问 → 按真实反馈迭代 → 看是否形成可复制的变现。反复出现的思路包括：新词最大价值往往是快速验证选词、需求和付费，而不是保证长期赚钱；不要用自己「这么简单我不会买」的习惯判断用户；产品应对准一个具体结果，而不是大而全平台；当天或数小时内上线很常见，但支付、生成、失败退款、积分回退、邮件、Webhook 和移动端必须至少完整走通一次；多个案例的主要用户和订单来自 ChatGPT 而非 Google，并列举了 Neo 约63%流量、85%收入，李理可约70%收入等自报比例，同时提醒不要把订单简单全部归因于 GEO 或 llms.txt；流量不必很大，几十个精准访客也可能下单；旧站可以加新词内页或给相关新站导流；价格上被提到较多的是约5美元体验包、约9.90美元单次购买、免费预览后在用户想再生成时收费，套餐不宜过多，低价档不要起成「缩水版」，价格要按模型成本倒推。文中用一张大表汇总已出单案例（含 Wu、Neo.Ye 的 Hotel Lobby、作者自己的 Migos AI、李理可、Rick、Kyro、Altman 的四个新词站等），结果从1单到逾100单不等；其中写 Altman「超过100单，单日超过1000美元」，与 AsHa 正文表格只给 UV 和付费人数、未写日收入并不完全一致，应分开看待。另提到游戏/攻略站广告收入不稳定，AdSense 常审核失败，Adsterra 即使有流量收益也低，支付被拒后尝试联盟导流尚未形成稳定收入，以及有老站加一个精准新词内页后第一次月入过千美元。短期机会被列成社媒爆发的模板和生成器、用户已看见效果但不会做、「上传—付款—拿结果」的一次性工具、ChatGPT 能引用的垂直页、竞争少但社媒仍活跃的新词、旧站内页和全球小额支付；中长期则是沉淀模板、共用登录支付、把新词验证做成订阅，以及自动化找词上线和外链资源库——后几项只是展望。普遍没做好的：犹豫错过按天甚至按小时计的窗口、过度追求完美、交付测试不足、埋点太晚、转化和套餐设计差、换脸或真人素材的支付与模型合规未评估、只看流量不看闭环、上线后不再运营。文末把流程收成发现、判断、竞争、变现、域名、当天 MVP、测交付、第一天埋点、获客、24–72小时调整、成本和合规、热点后复盘十二条。结论是：当前更常见的机会是用模板在极短窗口做出能交付、能收款、能被找到的垂直小工具，短板通常在行动速度、交付、数据和转化，而不是把产品做复杂。

## 方法 / 阈值
可作为对照清单的是：先声明数据不可直接加总；上线可以快，但收款和交付必须先走通；尽早接入来源和漏斗事件；用模型成本约束定价；涉及真人图片和换脸要先看模型和支付是否允许。表中金额都是转述自报，不能当审计结果，也不能把「当天必须上线」写成强制规则。外链、自动上线流水线不列入方法。

## 案例
Hotel Lobby、Zombie、Raindance、Gas Station Dance、Rap Duo 等多站的单量和金额均来自群友自报，时间窗口短，且可能重复。Altman 日入千刀是本篇转述，需与 AsHa 原文对照。作者自己的 Migos AI 约60单、约600美元同样是自报。

## 风险 / 冲突 / 实操注意
「特定角色」和换脸类生成器有版权、肖像和支付通道风险，文中已提到拒付与审核失败，只评述不跟做。不要把这份合集理解成保证能复制的国庆战报，更不要在未验证交付时批量上站。联盟导流和自动外链不执行。
