## 要点
2025-01-16 技术课。背景是有人写程序去爬 query.domains 的接口；作者改讲从注册局源头查域名是否已注册。概念：每个后缀有注册局，Godaddy 等是注册商（可理解为代理）；有的注册局会把技术管理外包；还有些网站只是注册商的再代理。注册数据在 WHOIS 服务器，按协议查询无需登录。IANA 维护顶级 WHOIS（whois.iana.org），可查到各注册局的 WHOIS 地址；各注册局、注册商也有自己的服务器。传统方式是连 43 端口，发送域名加回车得到文本。例如不知 .com 的服务器时，先向 IANA 查 com，得到 whois.verisign-grs.com，再查完整域名；查 ai 可得到 whois.nic.ai。不同注册局返回格式不同，需自行解析；已注册通常含注册人、注册与到期时间等，未注册也有可识别标志。.ai 注册局比较特殊，不返回注册和结束时间。详细信息里还能看到注册商 WHOIS，但多年前为保护隐私，注册商侧往往不再给出更细信息，若只为确认是否注册及注册/到期时间，通常不必再查注册商。作者总结：批量查询时 WHOIS 才是一手信息，不必到处找 API；但提醒「有些小注册局会限制单个 IP 短时间查询次数，所以需要用多个 IP 去查」。学员 Airyland 补充：43 端口是上一代协议，不少注册局已支持 RDAP，走 HTTP 返回 JSON。作者称自己没用过（文中误写为 RADP），并说自己在 Cloudflare Worker 里用 AI 写过一个未公开、后缀有限的 Whois API，仅自用。学员「那我不就可以拿老的 ai 域名来参加新词比赛了」，作者未直接回答，继续讲 WHOIS。作者还提到某服务「老是被人当接口，我没去维护了」。

## 方法 / 阈值
概念层可以记下：查是否注册应走注册局公开的 WHOIS 或更新的 RDAP，而不是去爬第三方网页接口。具体 socket 请求、正则抽取、多 IP 轮询和私有 Worker 实现都不写入、不复现。尊重各注册局的查询频率限制。

## 案例
用 chatgpt.com、.com、.ai 做查询路径演示；.ai 不返回时间是作者当时的观察。私有 Whois API 未公开，不作为可用工具。

## 风险 / 冲突 / 实操注意
用多个 IP 绕过查询次数限制，属于规避频率限制，不执行、不编写。不要把文中的查询步骤写成可运行脚本，也不要去调用或恢复作者未公开的接口。域名注册人信息属隐私，不回显截图中可能出现的联系人字段。拿老域名参加「新词比赛」是否合适，正文没有给出结论。
