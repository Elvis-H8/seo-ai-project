## 要点
2026-09-03，作者王焱讲如何用官方 Search Console API 拉取效果数据，而不是依赖后台导出的 1000 行上限，并一次拿到「词落在哪一页」。他不用 OAuth 弹窗，而是建服务账号、启用 Search Console API、下载 JSON 密钥（强调这就是密码，不要进仓库），再把服务账号邮箱加到 GSC 资源用户里，权限选「受限」即可读数。核心接口是 searchAnalytics.query：单次 rowLimit 最大 25000，用 startRow 翻页；建议只要已定稿数据（dataState=final），窗口结束日用「今天减三天」，以便和后台对齐；维度组合 ["query","page"] 一次给出词与落地页；国家是三位代码、设备是大写枚举，和后台导出不同，比较时要自己映射；可回溯约16个月。他在自己一个多语言工具站、同一28天窗口对比：后台导出1000行、曝光22764、占全站45227中的45.3%；API 拉到2050行、23935次曝光、占47.7%。多出的1050行总共只多1145次曝光、约30次点击。结论是：后台1000行其实已装下有分量的词；看不见的约52%是匿名化查询，后台和 API 都不给，换接口补不全。API 的价值主要在「词×页一次拿全」和可脚本化、可留档，不在「更多可见词」。踩坑包括：分析窗口要和脚本口径一致；先写入暂存、全部成功再替换，避免覆盖到一半失败；429 重试也要记账；排序要稳定以免两次结果洗牌；原始查询词不要进代码仓库。他认为偶尔看看排名或查询不足1000行时，不必接 API。

## 方法 / 阈值
这是官方 API 的用法说明，不是破解后台。只应在自己有权限的资源上、用最小只读权限进行。密钥不得入库、不得共享。文中的代码路径和完整函数不在此复述或代为运行。匿名化查询补不出，是接口共同的天花板。
