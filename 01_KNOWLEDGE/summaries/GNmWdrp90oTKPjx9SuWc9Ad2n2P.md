## 要点
作者介绍开源项目 Browser Hands（Chrome 插件 + 本机 MCP）：让 Claude Code、Codex 等 agent 直接操作本机已经登录的 Chrome，而不是再开无头浏览器。自称解决手填外链和导航站太慢、无头浏览器没有登录态且易触发风控的问题。评论区由 ZENGYUN 答复对比问题，说明作者或维护者身份与他有关。

## 方法 / 阈值
文称提供点击、填表、截图、读页面、跑脚本、传文件、录 GIF 等约 26 个工具；支持多 Chrome 配置文件，多 agent 各占一组标签。可用 quick_task 把多步交给快模型；碰到提交、付款、删除等不可逆按钮默认停下来等人确认。对比理由包括：标准 MCP、不绑 Claude 订阅；连已有 Chrome 比 Playwright 新开浏览器更稳；多 Google 账号靠 profile 切换；简单判断交给小模型省 token。安装在文中是一条从 GitHub Release 拉取脚本并交给 shell 执行的命令，项目地址为 github.com/214140846/browser-hands，MIT 协议。作者说自己用来批量发外链、提交导航、发 X 和提交 Product Hunt，本帖也是让 agent 发的，并附了约 20 秒填 PH 表单的演示。评论：有人拿它和 ego-browser 比，答复称更轻、并行更稳；有人提到官方浏览器插件，答复称 Codex 不稳、Claude 官方插件「道德感比较高」不愿代发外链，这个「解除了权限，道德感很低」，Hermes 等 agent 也能用。关于 Playwright 的追问没有完整答复收录。

## 案例
演示是 Product Hunt 的提交页，输入框里是示例网址，不是一份已核实的投放结果。

## 风险 / 冲突 / 实操注意
把已登录的浏览器交给 agent，等于把网站登录态交给自动化程序，有误操作和凭证风险。用它批量发外链、交导航、发帖，可能违反目标站条款，也被 Claude 官方插件有意限制。从网上下载脚本直接交给 shell 执行有供应链风险，安装前应自己审查，本库实践不执行这条命令，也不把该工具当作默认的外链作业流程。不可逆操作的确认机制不能替代对 agent 的人工监督。
